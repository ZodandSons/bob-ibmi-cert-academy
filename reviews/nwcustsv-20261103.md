## Findings

### HIGH — H1: Missing `SQLSTATE` check in `Cust_exists` (line 97)

| Field | Value |
|---|---|
| **Severity** | HIGH |
| **Location** | `nwcustsv.sqlrpgle:97` |
| **Issue** | `Cust_exists` checks only `sqlcode = 0`, not `SQLSTATE`. A network drop, row-not-found edge case, or warning state (class `01`) would return an incorrect `*on`/`*off`. |
| **Why it matters on IBM i** | `SQLCODE` alone cannot distinguish warnings (02xxx) from real errors. Shop standard and checklist rule require `SQLSTATE` to be checked after **every** SQL statement. |
| **Suggested fix** | ```rpgle<br>exec sql select 1 into :found<br>         from CUSTOMERS<br>        where CUSTOMERID = :pCustomerId<br>        fetch first 1 row only;<br>return sqlcode = 0 and found = 1 and NwU_sqlOk(sqlstate);<br>``` |

---

### HIGH — H2: `SQLSTATE` not checked after `EXEC SQL CLOSE CUSTLIST` in `Cust_openList` (line 239)

| Field | Value |
|---|---|
| **Severity** | HIGH |
| **Location** | `nwcustsv.sqlrpgle:239` |
| **Issue** | The `CLOSE CUSTLIST` is intentionally issued to reset the cursor when it may already be closed. The comment says "ignore not open", but **any other SQL error is also silently swallowed**. |
| **Why it matters on IBM i** | If the cursor is in an unexpected state (e.g. locked due to journal failure), the silent close will mask the problem and the subsequent `OPEN` may fail with a cryptic error. |
| **Suggested fix** | Accept only SQLSTATE `24501` (cursor not open) as an ignorable condition; treat anything else as a real error:<br>```rpgle<br>exec sql close CUSTLIST;<br>if sqlstate <> '00000' and sqlstate <> '24501';<br>  return sqlFail(err: 'Pre-close cursor');<br>endif;<br>``` |

### MEDIUM — M2: `ctl-opt` missing `dftactgrp(*no)` (line 13)

| Field | Value |
|---|---|
| **Severity** | MEDIUM |
| **Location** | `nwcustsv.sqlrpgle:13` |
| **Issue** | The `ctl-opt` is:<br>`ctl-opt nomain option(*srcstmt:*nodebugio) datfmt(*iso) timfmt(*iso);`<br>It omits `dftactgrp(*no)`. Although a `nomain` module built by `CRTSQLRPGI OBJTYPE(*MODULE)` cannot itself specify an activation group, the **shop standard** requires `dftactgrp(*no)` on all RPG ctl-opts, and its absence can cause confusion when reading or refactoring the source. |
| **Why it matters on IBM i** | `dftactgrp(*no)` is **mandatory** in shop rule 02 for new RPG. Omitting it is a standards deviation that could be copied into a future `pgm.sqlrpgle` variant. |
| **Suggested fix** | `ctl-opt nomain dftactgrp(*no) option(*srcstmt:*nodebugio) datfmt(*iso) timfmt(*iso);` |

### MEDIUM — M3: `Cust_fetchNext` silently discards fetch errors (line 259)

| Field | Value |
|---|---|
| **Severity** | MEDIUM |
| **Location** | `nwcustsv.sqlrpgle:259` |
| **Issue** | `if sqlcode = 100 or not NwU_sqlOk(sqlstate); return *off; endif;` — a true fetch error (e.g. SQLSTATE `22xxx` data conversion) is conflated with normal end-of-file and silently returns `*off` with no error reported to the caller. |
| **Why it matters on IBM i** | Callers cannot distinguish "no more rows" from "fetch failed". This can silently truncate a list with no operator visible error. |
| **Suggested fix** | Add an `err` parameter to the procedure interface (breaking change — coordinate with callers), or at minimum log via `NwU_sqlError` before returning `*off`. |

## Verdict

> **REQUEST CHANGES**

Two HIGH findings must be resolved before approval:
- **H1** (`Cust_exists` SQLSTATE gap) is a correctness bug — `Cust_validate` delegates duplicate/existence checks to this procedure and an incorrect `*on` return on a SQL error would silently pass invalid records through to INSERT or DELETE.

The MEDIUM findings (M1 header, M2 `dftactgrp`, M3 fetch error silencing) should also be addressed in the same PR. LOW items may be deferred.
